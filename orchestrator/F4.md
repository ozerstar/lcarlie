# F4 Action Firewall and human approval

F4 introduces a database-enforced proposal and approval boundary. AI may create only allowlisted, schema-validated action proposals through `core.ai_propose_action`. It cannot approve, reject, execute, or update action tables directly.

Human approvers may inspect pending payloads through `core.ai_get_pending_actions` and decide through `core.ai_decide_action`. Critical `TWO_PERSON` types cannot be approved until a later phase implements independent dual approval.

All action types have `execution_enabled=false`. No execution function, external API call, scheduler, or action worker exists in F4.
